# E0a Probe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Status (paused 2026-10-17):** Task 1 complete and reviewed (commits 93ef564, e8ca8a5). **Next: Task 2 (Native interop)** — not started, nothing committed. Open point for Task 2: confirm the `JOBOBJECT_FREEZE_INFORMATION` layout against SDK `winnt.h` (the plan says 16 bytes with edge filters; the implementer's recollection is 8 bytes). Execution scope: Tasks 1–7, then stop for user review of `Invoke-E0aProbe.ps1` / `Remove-E0aProbe.ps1`.

**Goal:** A throwaway Windows probe that shows whether a standard account can launch a second standard account's processes into a job it owns, freeze and terminate them, and what it can do about agent processes outside that job.

**Architecture:** One elevated script you run creates two throwaway accounts, hands the agent password to the controller-side harness over an ACL'd named pipe, runs the harness twice (scheduled task, then Secondary Logon), and always tears down. All Win32/NT calls live in one C# file loaded by `Add-Type`. Pure logic sits in a module with Pester tests. Job mechanics are also testable without accounts or elevation through a self mode.

**Tech Stack:** Windows PowerShell 5.1, inline C# via `Add-Type` (.NET Framework), Pester 3.4.0 (preinstalled; use `Should Be` syntax, not `Should -Be`).

**Spec:** `docs/superpowers/specs/2026-10-17-e0a-probe-design.md`

## Global Constraints

- Account names exactly `ac-probe-ctl` and `ac-probe-agent`; description "AgentContinuum E0a probe - safe to delete"; members of Users only.
- Passwords: 32 characters from a cryptographic RNG, memory only. Never on disk, in logs, command lines, environment, clipboard or Credential Manager. Exception: Task Scheduler holds `ac-probe-ctl`'s password until `ac-probe-ctl-runA` is deleted.
- No elevated command is ever run by the implementer. Elevated scripts are written and unit-tested with mocks only; you run them.
- Every probe-launched process: `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <script>`. Never change machine execution policy.
- `Add-Type` failure → `native_load_blocked` result with error text; no workaround.
- Never read, write or set `~\.claude`, `~\.codex`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`.
- Results schema `ac-probe-e0a/1`; every file carries `"edition": "Windows 11 Home"`, `os_caption`, `build` (`CurrentBuild.UBR`), `display_version`.
- Thresholds: freeze gap ≥ 5 s with no beat after freeze + 0.5 s, resume ≤ 2 s after thaw; terminate and kill-on-close within 5 s; run timeout 5 min; heartbeat every 250 ms; beacon lifetime ≤ 60 s.
- Paths: `C:\ProgramData\ac-probe\{bin,ctl,exchange}`, `C:\ProgramData\ac-probe-results\<yyyyMMdd-HHmmss>\`.
- Work on branch `e0a-probe` off `master`.

## Review Focus

1. **Torn heartbeat line**: the harness reads while the child appends, so the last line may be partial. The reader skips unparseable lines and doesn't throw. Test in Task 1.
2. **Leftovers from a crashed earlier run**: accounts, tasks or profiles may already exist at start. Pre-clean removes them, and every teardown step accepts both "present" and "already gone". Test in Task 6.
3. **Profile still loaded at teardown**: `.Delete()` fails while a process holds the profile. Teardown kills processes first, retries 5× at 2 s intervals, reports the failure, and keeps going with the other steps. Test in Task 6.
4. **Harness exits mid-freeze**: a crash or timeout while the job is frozen must not leave frozen agent processes behind. The harness thaws in `finally`, and the run script's timeout kill plus teardown ends them anyway. Test in Task 4.
5. **`Add-Type` blocked**: the harness or child writes a `native_load_blocked` result instead of crashing with no file. Test in Task 2.

### Task 1: Common module (pure logic)

- Test: `probes/e0a/tests/ProbeCommon.Tests.ps1`

**Interfaces:**

### Task 2: Native interop

**Files:**
- Create: `probes/e0a/Native.cs`, `probes/e0a/ProbeNative.psm1`
- Test: `probes/e0a/tests/ProbeNative.Tests.ps1`

**Interfaces:**
- Produces: `Import-ProbeNative [-SourcePath <string>] -> [pscustomobject]@{Loaded bool; Error string}`. It never throws, and it defaults to `Native.cs` next to the module. Static class `AcProbe.Native` with:
  - `IntPtr CreateKillOnCloseJob()`: `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` only, no breakaway flags.
  - `bool IsInJob(IntPtr proc, IntPtr job)`: `IntPtr.Zero` means "any job".
  - `int[] JobPids(IntPtr job)` (`JobObjectBasicProcessIdList`); `int JobActive(IntPtr job)` (`JobObjectBasicAccountingInformation.ActiveProcesses`).
  - `int SetJobFreeze(IntPtr job, bool freeze)`: returns NTSTATUS. Uses `NtSetInformationJobObject`, class 18, `JOBOBJECT_FREEZE_INFORMATION { uint Flags /*FreezeOperation=1*/; byte Freeze; byte Swap; ushort Reserved; uint HighEdgeFilter; uint LowEdgeFilter }`, 16 bytes. Confirm the layout against SDK `winnt.h`.
  - `int SuspendProcess(IntPtr proc)` and `int ResumeProcess(IntPtr proc)`: NTSTATUS.
  - `ProcInfo StartAsUser(string user, string domain, string password, string cmdLine, bool suspended)`: `CreateProcessWithLogonW`, `LOGON_WITH_PROFILE`, optional `CREATE_SUSPENDED`. `ProcInfo{IntPtr Process; IntPtr Thread; int Pid; int Win32Error}`.
  - `ProcInfo StartSelf(string cmdLine, bool suspended, bool breakaway)`: `CreateProcessW`, optional `CREATE_BREAKAWAY_FROM_JOB`.
  - `bool Assign(IntPtr job, IntPtr proc)`, `int Resume(IntPtr thread)`, `bool TerminateJob(IntPtr job)`.
  - `OpenResult TryOpen(int pid, uint access)`: `{bool Ok; int Win32Error; IntPtr Handle}`.
  - `bool KillPid(int pid)`; `long CreationTime(int pid)`: FILETIME, or -1 on failure.
  - `int LastError` captured on each call.
  - LSA (admin only): `string[] AccountRights(string sid)`, `int AddRight(string sid, string right)`, `int RemoveRight(string sid, string right)`.
  - `PipeOpen CreateFirstInstancePipe(string name, byte[] securityDescriptor)`: `CreateNamedPipeW` with `PIPE_ACCESS_OUTBOUND | FILE_FLAG_FIRST_PIPE_INSTANCE` (0x00080000), `PIPE_TYPE_BYTE | PIPE_REJECT_REMOTE_CLIENTS`, max instances 1, and `SECURITY_ATTRIBUTES` from the self-relative SD bytes. Returns `PipeOpen{Microsoft.Win32.SafeHandles.SafePipeHandle Handle; int Win32Error}`; `Handle` is invalid on failure (e.g. 231 `ERROR_PIPE_BUSY` / 5 `ERROR_ACCESS_DENIED` when the name already exists).

### Task 3: Child and beacon

**Files:**
- Create: `probes/e0a/Child.ps1`, `probes/e0a/Beacon.ps1`
- Test: `probes/e0a/tests/Child.Tests.ps1`

**Interfaces:**
- Consumes: `Import-ProbeNative`, `AcProbe.Native` (Task 2).
- Produces: `Child.ps1 -Exchange <dir> -Mode <Heartbeat|Grandchildren|Breakaway|Escape|Isolation> [-HarnessPid <int>] [-CtlDir <dir>] [-ResultsDir <dir>] [-BinDir <dir>]`. It writes:
  - Heartbeat (all modes): appends `[datetime]::UtcNow.ToString('o')` to `<Exchange>\heartbeat.txt` every 250 ms, until killed or for 120 s.
  - `Grandchildren`: starts two `Child.ps1 -Mode Heartbeat` children with heartbeat files `heartbeat-g1.txt` and `heartbeat-g2.txt` (heartbeat file name parameter `-BeatFile`, default `heartbeat.txt`).
  - `Breakaway`: `StartSelf(...,breakaway=$true)` for a grandchild, then writes `breakaway.json` `{ok; win32_error; pid}`.
  - `Escape`: `Register-ScheduledTask ac-probe-agent-escape` with `New-ScheduledTaskPrincipal -UserId $env:USERNAME -LogonType S4U`, action `Beacon.ps1 -Exchange <dir>`, then `Start-ScheduledTask`. Writes `escape.json` `{registered; register_error; started; start_error}`.
  - `Isolation`: writes `isolation.json` with six entries `{name; ok; error}`: `ctl_read`, `ctl_write`, `results_read`, `results_write`, `open_harness_terminate` (0x0001), `open_harness_vmwrite` (0x0020|0x0008).
  - Native load failure: writes `child-native.json` `{result:'native_load_blocked'; error}` and exits 3.
- `Beacon.ps1 -Exchange <dir>` writes `beacon.json` `{pid; started_at}`, then heartbeats `heartbeat-beacon.txt` for 60 s and exits.

### Task 5: Cross-account harness parts and secret pipe

**Files:**
- Create: `probes/e0a/ProbeSecret.psm1`
- Modify: `probes/e0a/HarnessChecks.psm1` (C2, C7, C8), `probes/e0a/Harness.ps1` (A/B launch path)
- Test: `probes/e0a/tests/ProbeSecret.Tests.ps1`

**Interfaces:**
- Produces:
  - `New-ProbeSecretPipe -AllowedSid <string> -Secret <SecureString> [-Name <string>] [-DaclSid <string>] -> [pscustomobject]@{Name; Job}`.
    - The pipe name defaults to `ac-probe-` plus 16 random hex characters. `-Name` is for tests.
    - The pipe is created synchronously, before the function returns, via `[AcProbe.Native]::CreateFirstInstancePipe`. If the name already exists the function **throws** `"pipe name already in use (win32 <code>)"` and no secret is ever handed to anything.
    - The DACL grants Read to `DaclSid` only (default `AllowedSid`; `-DaclSid` is test-only). There's no creator ACE, because the server already holds its handle.
    - A background runspace serves exactly one connection, in this order:
      1. Wait for the client (30 s timeout).
      2. Identify the client: `RunAsClient` → `WindowsIdentity.GetCurrent().User.Value`.
      3. If the SID equals `AllowedSid`, write the secret as UTF-16LE, `WaitForPipeDrain`, and record `delivered`. Otherwise write nothing and record `client_sid_mismatch:<sid>`.
      4. Disconnect and dispose.
    - The outcome is readable via `Receive-Job` on `Job`. A second client always fails, because the only instance is gone.
  - `Receive-ProbeSecret -PipeName <string> [-TimeoutMs 10000] -> SecureString`. It connects with `TokenImpersonationLevel.Identification`, so the server can read its SID but can't act as it. It reads to end of stream, and throws if it gets zero bytes.
  - In `Harness.ps1`, for A/B: `Receive-ProbeSecret`, then `Ctx.Launch` calls `StartAsUser('ac-probe-agent', '.', <plain>, ...)`. The plaintext lives in a `char[]`/BSTR that is zeroed right after the call, and it is never put in a variable that gets logged.
  - `Invoke-C2LaunchAssign`, `Invoke-C7Escape` and `Invoke-C8Isolation` follow the spec. In C7 the beacon PID comes from `beacon.json` (30 s wait). The harness checks `Get-Process -Id`, `CreationTime`, `IsInJob(handle, job)` and `KillPid`, then confirms `heartbeat-beacon.txt` stops.
